[Hands-on] ActivityGen: From Group-Chat Plans to a WeChat Activity-Circle Mini Program

“可别这么宅” is a WeChat Mini Program for organizing offline activities in group communities. It evolved from activity creation and sign-up into a community collaboration tool with circles, member roles, approvals, notifications, comments, and multi-circle switching.

The work was not about accumulating screens. It was about turning loose group-chat coordination into trackable state, explicit permission boundaries, and a stable experience inside the WeChat ecosystem.
1 / 8
01

Why it exists: chat is good for conversation, not activity management

Starting an activity in a WeChat group is natural, but sign-up lists, time and place, capacity, permissions, and later changes quickly disappear into message history. ActivityGen turns these into structured activities and uses an “activity circle” as the persistent home for a community.

Centralized information

Name, time, location, capacity, images, and instructions live together.

Trackable sign-ups

Join, leave, capacity limits, and participant lists have explicit state.

Community boundaries

Activities belong to a circle; non-members cannot access restricted interactions.

Actionable changes

Approvals, edits, cancellations, applications, and role changes can notify relevant people.

03

Architecture: WeChat Mini Program + CloudBase

Mini ProgramWXML · WXSS · JavaScript
wx.cloudDatabase · Storage · Functions
CloudBasePersistent state and privileged operations

Native Mini Program pages

13 pages, no frontend framework or build step, with a custom four-tab bar.

Cloud Database

activities, groups, members, comments, wishes, and notifications.

Cloud Storage

Stores activity images and avatars; cloud:// file IDs are resolved to temporary HTTPS URLs before rendering.

Seven Cloud Functions

Handle OpenID, participation, pinning, group administration, wishlists, notifications, and openGId decryption.

Permission boundary

Writes requiring elevated privileges—participation, pinning, and group administration—run through Cloud Functions rather than relying on direct client database permissions.

Flicker during tab changesSWR on home, activity, and member pages: show cache first, refresh silentlyNever clear visible data before a silent fetch

06

Key takeaways

Stable identity comes first

Without stable OpenID, roles, participation, and cross-device data become fragile.

Caching is part of product experience

SWR makes pages visible immediately, then refreshes in the background; writes must invalidate the right caches.

Permissions belong server-side

The client presents actions; Cloud Functions validate and execute privileged writes.

State complexity grows quickly

Approval, rejection, voiding, expiration, organizer, and membership combinations eventually need an explicit state machine.

Next technical debt

The activity-detail action bar still relies on complex condition priority; cross-page state is split across LocalStorage and globalData; WeChat platform constraints are documented rather than linted. Explicit state mapping and custom ESLint rules would improve maintainability.

What the project demonstratesActivityGen’s core achievement is not the number of screens. It is turning loose group-chat coordination into stable identity, circle boundaries, activity state, role permissions, notification events, and a recoverable client experience.
