[Hands-on] ActivityGen：从微信群约活动到活动圈小程序

“可别这么宅”是一款帮助微信群组织线下活动的微信小程序。从最初的活动创建与报名，逐步演进为包含活动圈、成员角色、审批、通知、留言和多圈切换的社区协作工具。

这次实践的重点不是堆功能，而是把微信群里分散的约活动流程，转化为可追踪的状态、明确的角色权限，以及在微信生态中稳定运行的产品体验。
1 / 8
01

为什么做：群聊适合沟通，不适合管理活动

微信群发起活动很自然，但报名名单、时间地点、人数限制、成员权限和后续变更容易散落在聊天记录中。ActivityGen 将这些信息沉淀为结构化活动，并用“活动圈”承载一个群体持续发生的线下活动。

信息集中

活动名称、时间、地点、人数、图片和说明集中展示。

报名可追踪

报名接龙、人数上限和取消报名都有明确状态。

组织有边界

活动属于特定圈子，未入圈用户不能参与受限互动。

变化可通知

审批、活动修改、作废、成员申请和角色变化均可通知相关人。

产品能力：从活动工具扩展为活动圈

创建圈子名称、介绍、公告

活动生命周期

创建、待审批、通过、拒绝、修改、置顶、作废和结束。

成员与角色

创始人、主理人、核心成员、普通成员；支持审批、调角色和移除。

互动与通知

报名接龙、活动留言、收藏、应用内通知和微信订阅消息。

主要页面作用
首页圈子公告、统计、置顶活动和快速创建入口
活动全部、即将开始、我创建、我参加等筛选
成员成员列表、申请审批、角色与个人活动统计
我的资料、收藏、通知、圈子切换和管理入口
03

技术架构：微信小程序 + CloudBase

Mini ProgramWXML · WXSS · JavaScript
wx.cloudDatabase · Storage · Functions
CloudBase持久状态与高权限操作

原生小程序页面

13 个页面，无前端框架和构建步骤，使用自定义四栏 Tab Bar。

Cloud Database

activities、groups、members、comments、wishes、notifications。

Cloud Storage

保存活动图片和头像；前端先将 cloud:// FileID 解析为临时 HTTPS URL。

7 个 Cloud Functions

处理 OpenID、报名、置顶、圈子管理、心愿单、通知和 openGId 解密。

权限边界

报名、置顶和圈子管理等需要提升权限的写操作进入 Cloud Functions，而不是直接依赖客户端数据库写权限。

04

关键工程决策

问题处理方式得到的经验
用户身份不稳定从本地随机 ID 迁移到微信 OpenID，并让页面等待 userIdReady身份是权限与跨设备数据一致性的基础
云图片跨设备失效上传到 Cloud Storage，批量解析临时 URL，并缓存 90 分钟cloud:// 不是可直接渲染的永久 URL
页面切换闪烁首页、活动和成员页采用 SWR：先显示缓存，再静默刷新不要在 Silent fetch 前清空已有数据
角色和审批复杂用成员记录和 Cloud Functions 控制创始人、主理人、核心成员和成员权限UI 隐藏不是授权；权限必须在数据写入层落实
微信平台限制遵守 WXML 条件兄弟节点、模板表达式、Tab 跳转和订阅消息规则平台 Footgun 应逐步转化为自动检查

06

Key takeaways

稳定身份必须优先解决

没有稳定 OpenID，角色、报名和跨设备数据都会变得脆弱。

缓存策略是产品体验的一部分

SWR 让页面立即可见，再后台更新；缓存失效点必须跟写操作联动。

权限要落在服务端

客户端负责展示，高权限写入由 Cloud Functions 验证和执行。

状态复杂度会快速增长

审批、拒绝、作废、过期、组织者和成员身份组合，最终需要显式状态机。

下一步技术债

活动详情底栏仍依赖复杂条件优先级；跨页状态仍散落在 LocalStorage 与 globalData；微信平台限制主要靠文档提醒，未来可用显式状态映射和 ESLint 自定义规则提高可维护性。

实践收获ActivityGen 的核心并不是“做了多少页面”，而是把微信群里的松散协作，逐步建模为稳定身份、圈子边界、活动状态、角色权限、通知事件和可恢复的客户端体验。
